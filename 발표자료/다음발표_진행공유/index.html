"가장 큰 변화는 성공 기준입니다. 축제 성과가 아니라 에이전트가 단계마다 쓸 만한 결과를 냈는지로 판단합니다. 축제 목표에 못 미쳐도 원인을 정확히 분석하고 개선안을 냈다면 에이전트는 제 몫을 한 겁니다."

전체 로직 — 메인 지침 하나, 파트 여러 개

1:00

메인 지침이 축제 전체의 기준을 잡고, 각 파트가 그 기준 안에서 자기 일을 한다.

①메인 지침서 — 축제 전제, 목표 우선순위, 근거 규칙, 윤리, 성공 기준. 모든 파트가 따르는 공통 규칙
②세부사항 확정 — 지침의 ❓ 항목을 회의로 결정 (서브 타깃, 요일, 3일 구성, 토론 참가 단위·심사 비율, 평가 컷오프, 일정, 실험 비율, 접근성·친환경)
③파트로 나누기 — 확정된 세부사항을 기준으로 축제를 파트 단위로 쪼갬
④파트마다 세 가지를 만든다
정보 정리그 파트에 필요한 자료조사 DB
파트 에이전트그 파트를 기획하는 에이전트
파트 기본 지침서규칙 + 프롬프트 (마스코트 IP 가이드 형식)
⑤통합·순환 — 파트 결과를 하나의 연도별 기획안(00~05)으로 묶고, 축제 뒤 결과가 다음 해 입력이 됨
빈칸 · 확인 필요파트 에이전트들을 누가 묶는지(메인 에이전트가 파트를 불러 쓰는지, 담당자가 순서대로 돌리는지)를 알려 주시면 ⑤를 확정해서 그리겠습니다.

"한 에이전트에 모든 걸 시키면 지침이 끝없이 길어집니다. 그래서 공통 규칙은 메인 지침에, 파트마다 필요한 정보와 규칙은 파트 지침에 나눠 담습니다."
