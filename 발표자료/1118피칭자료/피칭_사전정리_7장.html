피칭 구조 7장 — 우리 팀은 어디까지 왔나

문제 → 해결 → 시장 → BM → MVP → 팀 → 요청사항 순서로, main 저장소의 발표자료·세부지침안과 에이전트 구성도 v3를 대조했어요.
읽는 법. 가장 먼저 아래 ‘요약’을 보세요. ‘있다/없다’는 origin/main 파일 기준이에요. 다른 브랜치(kimseunghee의 D파트·Mascot·customer)와 노션은 보지 않았어요. 라벨 [확인] [해석] [가설] [추정] [가정]은 팀 지침을 그대로 썼어요.
구조 규칙. 표지 다음 바로 문제. 회사·팀 소개로 시작하지 않고, 마지막 장은 ‘감사합니다’가 아니라 요청사항 한 문장과 MVP URL.

요약 — 처음 보는 분을 위해

이 문서는 무엇인가
피칭 발표(7장 구조: 문제 → 해결 → 시장 → BM → MVP → 팀 → 요청사항)를 준비하면서, 지금 우리 팀 자료가 각 장을 얼마나 뒷받침하는지 점검한 문서예요. 2026-11-18 기준, 저장소 main의 발표자료·세부지침안과 에이전트 구성도 v3를 근거로 했어요.
우리는 무엇을 만드나
‘대구 사투리 축제’를 매년 열 수 있게 돕는 순환형 축제 기획 AI 에이전트예요. 기획 조건 입력 → 자료조사 → 기획안 → 운영 준비 → 성과 정리를 에이전트가 돕고, 그 결과가 다음 해 기획의 입력으로 돌아와요. 결정·외부 연락·계약은 사람이 하고, 근거 정리와 초안만 에이전트가 맡아요. 사이드 프로젝트로 축제 마스코트(대키미·외지몽)를 만들고, 시장 반응을 보려고 텀블벅 펀딩 ‘대구얼라들’(1월 오픈 목표)을 준비 중이에요.
왜 필요한가(문제)
대구는 ‘스쳐 가는 도시’예요. 체류시간이 전년 대비 1.5% 줄었고 서울에서 오는 비율은 1.0%예요(언론 보도, 원자료 확인 중). 또 축제는 해마다 열리지만, 판매·참여 결과가 다음 해 기획으로 돌아가는 고리는 참고한 두 사례(카카오프렌즈·대전 꿈돌이)에서도 확인되지 않았어요 [해석].
지금 어디까지 왔나
에이전트를 11개 파트(A 사투리 콘텐츠 ~ K 웹)로 나눠 파트별 지침서를 쓰는 단계예요. A·B·C·E·F·G·I·J·공통(P) 지침서가 main에 있고, D(굿즈)·H(운영)·K(웹)는 아직 없어요. 2027년 시범 기획안(00~03)과 모바일 안내페이지는 만들었고, 에이전트들을 하나로 묶는 통합·검증은 다음 단계예요.
7장 점검 결과
🟢 팀은 거의 갖춰졌고, 🟡 문제·해결·MVP는 일부만 있고, 🔴 시장·BM·요청사항은 거의 비어 있어요.
가장 큰 공백 3개
① 시장: 경쟁 비교표·포지셔닝 맵·SOM이 없어요. ② BM: 누가 돈을 내는지와 단위 경제가 없어요. ③ 요청사항: 청중에게 요청할 한 문장과 민감도 1위 가정이 없어요.
이번에 채울 순서
시장 → BM → 요청사항 → 문제(VOC) → 해결(As-Is→To-Be) → MVP(URL·가설 판정) → 팀(역할 표). 3·4·7장은 이어져 있어서 한 흐름으로 만들어요.
용어 풀이
서브 에이전트
에이전트를 역할별로 나눈 것. A 사투리 콘텐츠, B 10미·7구 맛집, C 플리마켓, D 굿즈, E 부대 프로그램, F 홍보, G 관광 연계, H 운영, I 성과, J 사투리, K 웹.
지침서(세부지침안)
각 서브 에이전트가 따르는 규칙·값을 적은 문서. 이 팀에서는 지침서가 에이전트의 ‘설계도’예요.
게이트(✅)
사람이 확인해야 다음 단계로 넘어가는 지점. 승인 기록이 없으면 에이전트가 진행하지 않아요.
[확인] [해석] [가설] [추정] [가정]
문장마다 근거 수준을 표시하는 팀 규칙. 확인=출처 있는 사실, 해석=우리의 해석, 가설=검증 전, 추정=계산한 예상, 가정=임시로 둔 값.
대키미·외지몽
축제 마스코트. 대키미는 대구 토박이 고양이 외계인, 외지몽은 얼라별에서 온 강아지 외계인 여행자.
10미·7구
대구 10미(공식 지정 대표 음식 10가지)와 대구 7개 구의 맛집을 모은 먹거리 구역.

1. 먼저 결정할 것 3가지

  1. 피칭하는 것이 무엇인가 — 11/18 중간발표6에서 메인 = 순환형 축제 기획 AI 에이전트, 사이드 = 마스코트·텀블벅 펀딩으로 정리됐어요. 피칭도 이 구조(에이전트가 주인공, 마스코트는 시장 검증 근거)로 갈지 확인해 주세요. 3장 시장·4장 BM의 기준이 이 선택에 달려 있어요.

  3. v1 MVP URL은 무엇인가 — 안내페이지 / 10/30 링크 / 구성도 v3 중 1개. 5장과 7장에 같은 URL이 들어가야 해요.

빠졌거나 부족한 것

  • 역할 표가 없어요. ‘파트 A~K ↔ 사람’ 대응표가 없고, D·H·K는 ‘담당 작성 대기’예요.
  • 사용 도구 기록이 없어요. 어느 단계에서 어떤 AI(Claude Code 등)를 썼고 사람이 무엇을 고쳤는지 한 장으로 정리된 곳이 없어요.
  • 발표자 표기가 회차마다 달라요(11/04·11/13·11/18 ‘먼크이성’, 11/09 ‘먼즈이성’, 발표자는 오민주·양유현 등으로 바뀜). 피칭 전에 팀 이름·표기를 통일해요.
  • 저장소 링크가 장에 안 붙어 있어요(‘작업 흔적(저장소)’ 항목).

채우는 방법

  1. 역할 표: 이름 / 맡은 파트·산출물 / 쓴 AI 도구 / 사람이 판단한 것.
  2. ‘AI 초안 → 사람 확인’ 사례 2~3개를 커밋 링크와 함께 보여 줘요(예: 결정기록 D-01, 지침 v1→v2 변경).
  3. 저장소 URL과 main 브랜치 핵심 폴더 3개만 소개.
  4. 팀 이름·발표자 표기 통일.

팀원 4명이 조사를 나눠 맡고, 11개 파트 지침서를 버전별로 쌓았어요. AI는 초안과 근거 정리에, 결정·외부 연락은 사람이 맡도록 규칙으로 고정했고 그 기록이 저장소에 남아 있어요.
