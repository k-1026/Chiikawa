# 기획 조건 확인 (지침 5장 1단계)

인자: `$ARGUMENTS` — 첫 단어는 연도(비어 있으면 먼저 묻는다). 두 번째 단어가 `갱신`이거나, 01이 이미 있거나, 사용자가 결정 사항을 알려 주면 **갱신 모드**(5장)로 간다.

## 1. 먼저 읽을 것
1. `local 리서치/<연도-1>/04_운영결과.md`, `05_차년도과제.md` — 있으면 핵심을 요약해 조건표 6장에 넣는다. 없으면 "과거 운영 데이터 없음"으로 적는다.
2. `local 리서치/통합_조사결과.md` 의 0장(원본 위치)과 7장(팀 공백)만 훑어 둔다.
3. `local 리서치/공통/단가표.md` 에 직전 연도 집행 실적이 있으면 예산 입력값 참고로 메모한다.
4. `local 리서치/<연도>/01_기획조건표.md` 가 이미 있으면 새로 만들지 않고 5장 갱신 모드로 간다.

## 2. 입력값 묻기 (지침 6장)
AskUserQuestion으로 한 번에 묻는다. 사용자가 "가정으로 진행"을 고르거나 답하지 않은 항목은 가정값을 쓰고 `[가정]` 표시를 한다.

| 구분 | 항목 | 미입력 시 처리 |
|---|---|---|
| 필수 | 개최 연도 | 반드시 받음 |
| 필수 | 연도 주제 | 에이전트가 후보 3개 제안 (02 조사 후 확정) |
| 필수 | 주최 | `[가정] 미정` — 예산·협찬 구조 판단이 제한됨을 적음 |
| 필수 | 예산 범위 또는 산정 요청 | `[가정] 에이전트 산정 요청` — 03 기획안에서 최소/기본/확장 3안 |
| 중요 | 예상 방문객 규모 | 통합본 5-1(치맥 관측값)을 참고한 `[추정]` 범위로 제시, 확정하지 않음 |
| 중요 | 협력 기관 | `[가정] 미정` |
| 중요 | 가용 인력 | `[가정] 미정` |
| 선택 | 전년도 운영 결과 | 1번에서 읽은 내용 |
| 선택 | 원하는 결과물 범위 | `[가정] 전체 기획안` |

## 3. 날짜·요일 확인
- 후보 날짜의 요일은 추측하지 않고 명령으로 확인한다. 예: `date -j -f %Y-%m-%d 2027-08-27 +%a` (macOS)
- 역산 일정의 날짜도 같은 방법으로 계산한다.

## 4. 새로 만들 때: 파일 2개 작성

### 4-1. `local 리서치/<연도>/01_기획조건표.md`

```markdown
# <연도> 대구 사투리 축제 — 01 기획조건표

> 작성일: YYYY-MM-DD · 기준 지침: local지침v1 · 상태: 초안(담당자 확인 전) · 결정 반영: 00_결정기록 D-00까지

## 1. 고정 조건 (지침 1장)
| 항목 | 설정값 | 상태 |
(기간 3일 / 8월 말 / 두류공원 / 메인 타깃 타지역 2030 / 목표 우선순위)

## 2. 입력값
| 구분 | 항목 | 값 | 출처(입력/가정/추정/확정 D-번호) |

## 3. 연도 주제 후보 (주제 미입력 시)
| 후보 | 한 줄 설명 | 체류·상권·사투리 연결 | 근거 자료 |

## 4. 핵심 일정 가정
(<연도> 8월 말 3일의 후보 날짜를 요일과 함께 2~3개. 대학 개강일 전인지 표시. 요일은 3장 방법으로 확인)

## 5. 이번 연도 범위
(고정 3대 프로그램 / 연도별 변경 항목 / 조건부 변경 항목 — 지침 3장 기준)

## 6. 전년도 이어받을 것
(직전 연도 05_차년도과제 요약 또는 "과거 운영 데이터 없음")

## 7. 담당자 확인 필요
| # | 항목 | 지금 값 | 왜 필요한가 | 언제까지(8장 역산 기준) |

## 8. 연간 추진 일정 (축제일 역산)
| 단계 | 할 일 | 축제 기준 | 날짜(후보 ① 기준) | 근거·상태 |
```

8장 작성 규칙:
- 아래 단계를 기본 틀로 쓰고, 축제 첫날을 D-day로 두어 역산한다.
  1. 예산 확보 (주최 기관 예산 편성·추경·공모 일정)
  2. 주관 기관 선정 (용역·위탁 발주)
  3. 장소 대관 신청 (두류공원 시설)
  4. 협력 기관 협약 (숙박·상권·10미 업소)
  5. **KPI 측정 준비** (숙박 연계 쿠폰·설문·카드 매출 협조 등. 03 KPI 측정 준비표와 연결)
  6. 토론 참가자 모집·선발, 10미·플리마켓 업체 모집·선정
  7. 온라인 사전 프로그램·홍보 시작
  8. 안전관리계획 제출, 신고·허가·보험
  9. 현장 리허설
  10. 축제 → 사후 설문·데이터 수집 → `/festival-review`
- 기관의 실제 마감·편성 시기를 확인하지 못했으면 기간을 `[가정]`으로 두고 "확인할 곳"을 적는다. 기한을 지어내지 않는다.
- 오늘 날짜 기준으로 이미 늦었거나 촉박한 단계가 있으면 표 위에 따로 경고한다.

### 4-2. `local 리서치/<연도>/00_결정기록.md`

```markdown
# <연도> 대구 사투리 축제 — 00 결정기록

> 담당자가 결정한 것만 적는다. 에이전트는 결정을 대신하지 않는다. 결정이 바뀌면 지우지 말고 새 번호로 추가하고, 이전 결정의 상태를 "번복(D-xx)"로 바꾼다.

## 결정 목록
| 번호 | 날짜 | 항목 | 결정 내용 | 결정자 | 근거·메모 | 상태 |
|---|---|---|---|---|---|---|

## 아직 결정 안 된 항목
(01의 7장 "담당자 확인 필요"와 같은 목록. 결정되면 위 표로 옮긴다)
```

## 5. 갱신 모드
1. `00_결정기록.md` 와 `01_기획조건표.md` 를 읽는다. 결정기록이 없으면 4-2 양식으로 만든다.
2. 사용자가 알려 준 결정을 결정기록 표에 새 번호(D-01, D-02 …)로 추가한다. 날짜·결정자를 모르면 묻는다. 결정자를 추측해 적지 않는다.
3. 01에서 해당 값을 바꾸고 출처를 `확정 D-번호`로 적는다. `[가정]` 표시를 지우고, 7장 목록에서 뺀다. 주제가 정해지면 3장은 "확정안 + 탈락안(이유)"으로 줄인다.
4. 01 머리말의 "결정 반영: D-번호까지"와 상태를 갱신한다. 모든 필수 입력값이 확정이면 상태를 `확정`으로 바꾼다.
5. 결정이 02·03에 영향을 주면(예: 주제·날짜·예산 변경) 이미 있는 02·03 파일 맨 위에 다음 경고를 넣는다. 본문은 고치지 않는다.
   `> ⚠ 00_결정기록 D-xx(항목) 이후 갱신 필요 — /festival-research 또는 /festival-plan 을 다시 실행`

## 6. 마무리
`대구사투리축제기획에이전트.md`의 "작업 마무리" 형식으로 보고한다. 새로 만들었으면 다음 단계로 `/festival-research <연도>` 를, 갱신했으면 다시 실행해야 할 단계를 안내한다.
