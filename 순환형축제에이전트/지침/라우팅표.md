# 라우팅 표 (부분 요청 모드)

> 담당자가 일부만 요청했을 때 오케스트레이터가 누구를 부를지 고르는 표다. `→`는 앞 결과가 필요해서 이어 부르는 순서다.
> 표에 없는 요청은 **임의로 정하지 않고** 담당자에게 어떤 파트 일인지 묻는다.

| 요청 유형 | 예시 요청 | 호출할 서브에이전트 | 같이 볼 원본 | 단계 검증 |
|---|---|---|---|---|
| 토론 · 사투리 콘텐츠 | 논제 다시, 심사 비율 | part-agent A → part-agent J (검수) | P0-10 | ethics-reviewer |
| 먹거리 | 부스 배치, 업소 모집 | part-agent B | P0-3, Y.지도, G-3 | conflict-checker |
| 플리마켓 | 셀러 선정, 수수료 | part-agent C | P0-6, Y.지도 | conflict-checker |
| 굿즈 | 굿즈 라인, 발주 | part-agent D | D-1 | ethics-reviewer (IP) |
| 부대 프로그램 | 체험 아이디어, 시간대 | part-agent E → (밖 연계 있으면) part-agent G | P0-4 | conflict-checker |
| 홍보 | 캘린더, 숏폼, 오프라인 | part-agent F → part-agent J (문구) | P0-7 | ethics-reviewer |
| 관광 · 1박 | 동선, 숙박, 쿠폰 금액 | part-agent G → part-agent H (금액) | P0-8 | evidence-auditor |
| 예산 · 인력 · 안전 | 예산 3안, 안전 체크 | part-agent H (A~G 결과 + 단가표 필요) | P0-6, 단가표 | conflict-checker (합계) |
| 동선 · 스탬프 | 스탬프 위치, 보상, 배부 | flow-designer (동선 · 찍는 지점) → part-agent H (배부 · 교환 · 상품) → part-agent G (G-3 밖 쿠폰) | P0-1, P0-3, Y.지도 | conflict-checker |
| 지도 · 구역 | 구역 번호, 바리게이트, 배치가 지도와 맞는지 | part-agent Y (지도 원본을 읽어 답하고 배치를 확인. 지도 수정은 지도 담당에게 질문) | 세부지침안/Y.지도 | conflict-checker |
| 성과 · 설문 | KPI, 설문지 | part-agent I | P0-2 | evidence-auditor · conflict-checker (일정) |
| 웹 기능 | 지도, 투표 화면 | part-agent K (+ 데이터는 part-agent J) | P0-3, Y.지도, flow-designer 결과 | format-checker |
| 결정 변경 | "주제 A안으로 정했어" | 부르지 않음. 오케스트레이터가 00_결정기록 추가 → 영향 파일에 ⚠ | 00_결정기록 | — |
| 조사 보강 | "유사 축제 더 찾아줘" | researcher | 통합_조사결과V1 | evidence-auditor |
| 지침 점검 | "지침 오류 찾아줘" | 검증 에이전트 6개 전체 | 세부지침안 목차들 | reviewer |
| 표에 없음 | 예: 식사 · 테이블 존, 3일 타임테이블 | 담당자에게 어떤 파트 일인지 묻는다 | — | — |

## 부분 요청 처리 순서
1. 00_진행상태 · 00_결정기록을 읽는다.
2. 위 표에서 에이전트를 고른다. 앞 단계 산출물이 없으면 그 사실을 적게 하고 진행한다. 수치는 팀 `[가정]` 파일에서만 가져온다.
3. 결과를 해당 단계 검증에 넘긴다 (재작업 최대 2회).
4. 반환의 '영향 파트'에 있는 파일 맨 위에 ⚠ 갱신 경고를 달고, 00_진행상태 "⚠ 파일" 목록에 추가한다.
5. 담당자에게 보고한다.
