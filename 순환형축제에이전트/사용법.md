# 순환형 축제 에이전트 사용법

> 대상: 축제 기획 담당자 · 작성 2026-11-18 · 상태: 팀 확인 전 (구버전 `로컬에이전트/`를 대신함)

## 1. 어떤 에이전트인가
- 담당자는 **오케스트레이터 하나하고만** 대화해요. 오케스트레이터가 단계마다 맞는 서브에이전트를 부르고, 단계 사이마다 검증 에이전트가 결과를 검사해요.
- 확인이 필요한 단계(✅ 5곳)에서는 멈추고 담당자 승인을 기다려요.
- 모든 결정과 진행 상태가 파일에 남아서, 대화가 끊겨도 이어서 하고 다음 해에도 다시 읽어요.

## 2. 처음 한 번 준비
```bash
git switch main
git pull
```
그다음 레포 안의 **`순환형축제에이전트/` 폴더**를 Claude Code(데스크톱 앱, 터미널 `claude`, VS Code 확장 중 아무거나)로 열어요.

## 3. 쓰는 방법
말로 해도 되고 명령을 써도 돼요.

| 하고 싶은 것 | 말로 | 명령 | 단계 |
|---|---|---|---|
| 새 연도 시작 | "2028 축제 기획 시작해줘" | `/festival-start 2028` | S0~S1 ✅ |
| 결정 알려 주기 | "주제 B안으로 정했어" | `/festival-start 2028 갱신` | 결정기록 |
| 조사 · 문제 정의 | "조사보고서 만들어줘" | `/festival-research 2028` | S2~S3 |
| 기획안 | "기획안 만들어줘" | `/festival-plan 2028` | S4~S10 ✅✅✅ |
| 일부만 | "토론 논제만 다시 짜줘" | `/festival-plan 2028 토론 논제` | 부분 요청 |
| 이어 하기 | "어제 하던 거 계속해줘" | 아무 명령 | 멈춘 단계부터 |
| 축제 끝난 뒤 | "결과 정리해줘" | `/festival-review 2028` | S11 ✅ → 다음 해 |

## 4. 꼭 알아 둘 것
- **결정은 사람이 해요.** 에이전트가 낸 후보 · 점수는 비교용이에요.
- 파일 맨 위에 **"⚠ … 갱신 필요"** 가 보이면 결정이 바뀐 거예요. 안내된 단계를 다시 실행해요.
- **KPI 측정은 축제 전에 준비해야 해요.** 기획안 14-1 "KPI 측정 준비표"대로 준비하지 않으면 결과 정리 때 "측정 안 됨"만 남아요.
- **첫해에는 예산 · 방문객 · 단가 같은 수치를 팀이 직접 넣어 줘요.** 파일 이름에 `[가정]`을 붙여 **`local 리서치/가정값/` 폴더에만** 두세요 (예: `[가정]_예산_대분류.csv` — P0-6 양식 열 그대로). 에이전트는 이 값만 쓰고, 없는 수치는 "미입력"으로 두고 물어봐요.
- 2년 차부터는 전년도 실제 집행액이 `대사투/공통/단가표.md` 에 쌓여서 그걸 먼저 써요. 견적서를 받으면 1장에 넣어 두세요.
- H(운영) · K(웹) 세부지침안이 아직 없어서, 이 파트는 에이전트가 틀만 만들고 질문으로 돌려줘요.

## 5. 파일이 생기는 곳 (`대사투/<연도>/`)
| 파일 | 내용 |
|---|---|
| `00_결정기록.md` | 담당자 결정 · 게이트 승인 |
| `00_진행상태.md` | 지금 몇 단계인지, 재작업 횟수, ⚠ 파일, 모아 둔 질문 |
| `01` ~ `05` | 기획조건표 · 조사보고서 · 기획안 · 운영결과 · 차년도과제 |
| `local 리서치/가정값/` (팀 조사 폴더 쪽) | **팀이 넣는** `[가정]_…` 수치 파일 (첫해 예산 · 방문객 · 단가) |
| `03_파트/` | 파트별 기획 (A~K, M-6 동선) |
| `검토/` | 단계별 검증 결과 |

## 6. 팀 규칙
- 에이전트가 만든 파일은 **초안**이에요. `[가정]`(팀이 넣은 값), `[추정]`(그 값으로 계산한 것), "미입력"은 담당자가 확인해요.
- 파트 지침을 새 버전으로 올리면 `순환형축제에이전트/지침/세부지침안_버전.md` 의 그 파트 한 줄만 고쳐요.
- 커밋 · push는 에이전트가 알아서 하지 않아요. 확인한 뒤 요청하세요.
