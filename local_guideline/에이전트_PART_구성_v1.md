# 대구 사투리 축제 기획 AI 에이전트 — PART 구성 v1

> 작성일: 2026-11-04 · 상태: 초안 (팀 검토 전)
> 기준: 기본 지침 v1.1 (노션 "가장 기본 지침 로직"), 3차 중간발표 PPT (STEP 2 기능별 PART 세분화)
> 이 문서는 에이전트를 어떤 PART로 나누고, 각 PART가 어떤 일을 하고, 어떤 지침과 자료를 쓰는지 정리한 것이에요. PART별 기본 지침서는 PART 구성이 확정된 뒤 차례로 작성할 예정이에요.

---

## 1. 용어

| 용어 | 뜻 |
|---|---|
| 메인 에이전트 | 전체 흐름을 이끄는 에이전트. 입력 조건 확인, PART 결과 통합, 평가, 검증을 맡아요 |
| 기본 지침 | 메인 에이전트와 모든 PART가 따르는 공통 규칙 (현재 v1.1) |
| PART | 한 분야를 맡아 일하는 단위. 메인 에이전트가 필요할 때 불러서 일을 맡겨요 |
| PART별 기본 지침서 | 그 PART에만 적용되는 규칙. 기본 지침을 따르면서 고정 규칙·금지 사항·프롬프트를 정해요 |
| 자료 | 각 PART가 일할 때 쓰는 조사 자료와 데이터 |
| 자료 통합본 | 여러 PART 자료의 목차 겸 요약 (`통합_조사결과V1.md`) |

> 한 PART = 자료 정리(DB) + 개별 에이전트 + PART별 기본 지침서 (3차 중간발표 STEP 3)

---

## 2. 결과물 흐름

```
01 기획조건표 → 02 조사보고서 → 03 기획안 → 전용 웹페이지 → (축제) → 04 운영결과 → 05 차년도과제
```

- 한 번에 나오지 않고, 단계마다 담당자와 주고받으며 하나씩 나와요 (기본 지침 5장).
- 02 조사보고서를 보고 담당자가 방향을 정하면, 03 기획안이 그 방향으로 작성돼요.
- 04 운영결과에 쓰는 축제 데이터(결제, 웹페이지 체크인·투표 등)는 담당자가 직접 입력하지 않고 자동으로 연결할 예정이에요.

## 3. PART 나누는 기준

- 축제를 짜는 에이전트이므로 **3대 핵심 프로그램**(사투리 토론대회, 10미·7구 맛집, 소상공인 플리마켓)을 먼저 나눴어요. 기본 지침 0장·3장·8장에서 3대 프로그램은 매년 고정이고 기획안에 반드시 들어가야 해요.
- 그다음 축제에 더하는 콘텐츠, 모든 프로그램에 걸치는 공통 지원, 결과물 제작 순으로 나눴어요.
- PART 이름은 노션 "깃 파일 명 규칙"의 주제키워드를 최대한 따랐어요.

| 구분 | 뜻 | PART |
|---|---|---|
| 핵심 프로그램 | 매년 고정인 3대 프로그램 | A~C |
| 추가 콘텐츠 | 3대 프로그램 옆에 더하는 콘텐츠 | D~G |
| 공통 지원 | 모든 프로그램에 걸쳐 적용되는 일 | H~J |
| 결과물 제작 | 다른 PART 결과를 모아 별도 결과물로 만드는 일 | K |

## 8. 보류·주의 사항

1. **메인 에이전트 업무 과다**: 문서 초안까지 메인 에이전트가 맡으면서 업무가 많아졌어요 (01 기획조건표, 02 조사보고서 통합, 평가, 검증, 03 기획안 통합, 문서 초안). 너무 무거워지면 문서 초안을 별도 PART로 분리하는 것을 검토해요.
2. **성과 PART의 데이터 연결 분리 여부**: PART별 DB·에이전트 구축(STEP 3) 또는 통합·검증(STEP 4) 단계에서 다시 판단해요. 단, 플리마켓 셀러 모집 공고(2027년 4월경, D-120) 전에는 데이터 수집 방식(공용 결제 단말기 등)을 정해야 해요.
3. **기획조건표와 기본 지침의 관계**: 고정 조건 중복, 매년 바뀌는 값이 지침에 섞인 항목, `00_결정기록`과의 관계를 정해야 해요.
4. **기본 지침 0장 산출물 표 보완**: 사투리 검수 결과, 사투리 사전, 전용 웹페이지 추가 여부를 정해야 해요.
5. **웹페이지 시안과 현재 자료 차이**: 장소 배치(2·28 자유광장 사용 여부), 7구 맛집거리 누락, 캐릭터 이름(대키미·외지몽과 다름)이 다르며, 프로젝트 후반부 웹페이지 작업 때 반영해요.
6. **PART별 기본 지침서 작성**: 지금 제대로 갖춰진 PART는 D. 굿즈 하나예요. PART 구성이 확정되면 차례로 작성해요.
