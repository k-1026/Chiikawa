### 0-2. 방문객 지도 구성 (전체지도·배치도)

> **전체지도** = 실제 페이지 제목 "대사투! 페스티벌 지도" (예전엔 '윗지도'라고 불렀음). **배치도** = 실제 페이지 제목 "대사투! 페스티벌 구역 및 시설 배치도" (예전엔 '아래지도'). `[확인]` 지도 담당 (2026-11-25, 이름 정리)

> 아래 내용은 **ChatGPT에서 작업한 것을 지도 담당이 정리해 준 것**. 같은 원본 `최종_v18.json`(구역 10개, 시설 마커 39개, 2026-11-25 기준)을 두 지도가 함께 씀. `[확인]` 지도 담당 정리 (2026-11-24, 파일·개수 2026-11-25 갱신)
> 이미 되어 있는 것과 **앞으로 할 것**을 나눠 적음.

| | 전체지도 | 배치도 |
|---|---|---|
| 무엇 | 축제장 전체 구조를 한눈에 보는 **이미지 안내도** (PNG) | 확대·축소하고 움직이며 목적지를 찾는 **카카오맵** |
| 보여 주는 것 | 구역 **경계·이름**(색 말풍선 + 연결선), **축제 출입로**, **차량 통제** | **보기 버튼**으로 고른 것만: 처음 열면 **구역 로고(+ 무대·축제 출입로)**만, 시설 버튼을 누르면 그 시설만. 로고·마커를 누르면 이름이 뜸 |
| 안 보여 주는 것 | 화장실·의료실·수유실·더위쉼터·소방·응급차·무대 같은 **개별 시설 마커** (단, 보기 버튼으로 켜면 보임) | 구역 경계(도형)는 전체지도에서 보여 줌 |
| 차량 통제 | **말풍선 글자**("차량 통제")로 표시 + 점·연결선. 범례에도 이름으로 한 번 더 안내 | **원형 배지 아이콘**(`badge-barricade-gray-2.svg`, 25px) |

**나눈 이유:** 경계와 시설을 한 지도에 모두 올리면 정보가 겹쳐 필요한 곳을 찾기 어려움. 전체지도로 전체 배치와 구역 관계를 먼저 보고, 배치도로 실제 위치를 찾게 함.

**배치도 아이콘 규칙**
- 구역 대표 표시(로고)는 **구역 도형마다 하나씩**. 같은 이름 구역이 여러 곳이면 **각 도형에 하나씩** (예: 7구 맛집거리 두 곳 모두). → 지도제작규칙 미확정 6번(라벨 반복 여부)의 답.
- 기본 위치: 원형은 중심, 다각형은 내부 좌표. 담당자가 위치를 조정하면 **그 위치를 우선**. (조정 위치를 저장할 칸은 아직 없음 — 앞으로 할 일)
- 크기: 아이콘은 **기본 25×25px**로 만든다. 담당자가 **강조해야 하는 아이콘**이라고 판단해 요청하면(예: 무대 아이콘) **40×40px**로 만든다. 지금 40px인 것은 무대·축제 출입로. 구역 대표 표시는 고정 크기 아이콘이 아니라 **구역 로고**를 쓰므로 이 크기 규칙과 다름 → 4-1-1 참고. `[확인]` 지도 담당 (2026-11-25)
- 사투리한마당 무대와 밥 묵자! 존의 **메인무대 생중계 화면은 같은 무대 아이콘**을 쓰고 이름으로 구분.

**전체지도 이미지를 만드는 방식 (목표)**
1. 담당자가 구역·시설·출입로·차량 통제를 편집하고 **한 번 저장**한다. 전체지도용 데이터를 따로 고르지 않는다.
2. 저장된 원본에서 전체지도에 필요한 구역·축제 출입로·차량 통제만 골라낸다.
3. 렌더링 코드가 **원본 좌표로** 경계와 색을 그리고 이름표·차량 통제 아이콘을 놓는다. GPT를 연결하면 이름표 겹침·스타일 제안만 맡김 (경계·위치는 원본 데이터로 그림).
4. 만든 PNG를 전체지도에 표시하고 배치도도 같은 저장본으로 갱신한다.

**배치도 위 플로팅 버튼** `[확인]` 지도 담당 (2026-11-25)

> 배치도(카카오 지도) **지도 화면 위에 떠 있는** 버튼 세 종류. 지도 아래 **범례**(6-1장)와는 다른 것 — 범례는 설명표, 플로팅 버튼은 실제로 누르는 조작부임.

| 버튼 | 위치 | 역할 |
|---|---|---|
| **보기 버튼 줄** | 지도 맨 위, [구역] [시설 전체] [화장실] ... 가로로 늘어섬 | 지도에 무엇을 보여 줄지 방문객이 직접 고름 (아래에 동작 자세히 설명) |
| **확대·축소 버튼** | 지도 왼쪽 아래 | 지도를 크게·작게 봄 (카카오 지도 기본 버튼) |
| **스카이뷰 전환 버튼** | 지도 오른쪽 아래, [지도 \| 스카이뷰] | 일반 지도 ↔ 위성 사진으로 바꿔 봄 |

**보기 버튼 줄 동작**
- 구역 로고·시설 아이콘을 한 화면에 다 올리면 서로 겹쳐 복잡해지는 문제를, **방문객이 보고 싶은 것만 고르게** 해서 해결함.
- **맨 처음 열었을 때:** [구역] 버튼이 켜져 있고, **구역 로고 + 무대 + 축제 출입로**만 보임. 화장실 같은 시설은 숨어 있음.
- **[시설 전체]를 누르면:** 구역 로고는 숨고, **모든 시설 아이콘**이 한꺼번에 보임(차량 통제 포함).
- **시설 버튼(예: [화장실])을 누르면:** 그 시설만 보임. 다른 건 다 숨음.
- **이미 켜진 버튼을 다시 누르면:** 처음 상태([구역])로 돌아감. 한 번에 하나만 켜짐 — 여러 버튼을 동시에 켤 수 없음.
- **버튼 순서:** 화장실 → 더위쉼터 → 의료실 → 소방·응급차 → 수유실 → 축제 출입로 → 무대 → 분실물센터. (차량 통제는 버튼이 따로 없고 [시설 전체]로만 봄 — 이름이 길어 버튼 줄이 너무 길어지는 것을 막기 위함, 4-1-1과 같은 이유)
  - **순서를 정한 기준** `[확인]` 지도 담당 (2026-11-25): 가나다·코드 순이 아니라 **"방문객이 자주 찾을 것 같은 순서" + "서로 관련 있는 시설끼리 묶기"**. 화장실·더위쉼터(누구나 자주 찾음) → 의료실·소방응급차(응급·안전 한 쌍) → 수유실(특정 방문객용 편의) → 축제 출입로·무대(길 찾기용) → 분실물센터(상대적으로 드묾) 순.

### 0-3. 지도 만드는 법 (기술 사양)

> **이 장의 목적:** 이름·색·아이콘 규칙(1~9장)만으로는 실제로 지도를 "만들" 수 없음. 이 장은 **AI 에이전트나 개발자가 이 문서만 보고도 festival-map과 같은 지도를 처음부터 만들 수 있도록**, 쓰는 기술과 파일 구조·데이터 형식·설정 방법을 적음. `[확인]` 지도 담당 (2026-11-25)

**기술 스택**
- **카카오맵 JavaScript API**로 지도를 그림. SDK는 `autoload=false`로 불러오고 `kakao.maps.load(...)` 콜백 안에서 지도를 만듦. 라이브러리는 `services`(주소→좌표 검색), 관리자 화면은 `services,drawing`(도형 그리기 도구) 추가.
- **Vite**(버전 6, vanilla JS, 프레임워크 없음)로 개발 서버·빌드를 돌림. `npm run dev`(개발), `npm run build`(배포용 `dist` 폴더 생성), `npm run preview`(빌드 결과 미리보기).
- 카카오 JavaScript 키는 **`.env`** 파일의 `VITE_KAKAO_MAP_KEY`에 넣음(공개 문서·저장소에 올리지 않음). 카카오 개발자 사이트에 **`http://localhost:5173`** 을 등록 도메인으로 등록해야 로컬에서 동작함(포트 고정, `vite.config.js`의 `server.strictPort`).

**프로젝트 폴더 구조**
```
festival-map/
├─ index.html              # 페이지 뼈대 (topbar + 지도 영역)
├─ src/
│  ├─ main.js              # 시작점: SDK 로드 → 지도 생성 → 관리자/방문객 화면 분기
│  ├─ config.js            # 처음 화면 장소, 구역 로고(ZONE_LOGOS), 시설 유형·아이콘 기본값
│  ├─ initialView.js       # 처음 화면 범위(좌표 찾기·setBounds) 계산

│  ├─ layers.js            # 구역(도형) 그리기
│  ├─ overview.js          # 전체지도(캔버스로 그리는 PNG 안내도) 생성

│  ├─ admin/               # 관리자 편집 화면 (개발 모드에서만 포함, 배포본에는 안 들어감)
│  └─ style.css            # 전체 화면 스타일

   └─ 최종_vN.json          # **방문객 지도가 실제로 읽는 데이터 원본** (아래 참고)
```

**데이터 파일 형식 (`지도 json/최종_vN.json`)**
구역·마커·아이콘 설정을 담은 JSON 하나가 전체지도·배치도 **공통 원본**임. 큰 틀:
```json
{
  "format": "festival-map-zones",
  "version": 3,
  "savedAt": "ISO 날짜",
  "zones": [ /* 구역(도형) 목록 */ ],
  "markers": [ /* 시설 마커 목록 */ ],
  "facilityTypes": [ /* 시설 유형별 이름·아이콘 설정 */ ]
}
```
- **구역(zone) 하나:** `{ id, name, type(polygon|polyline|arrow|circle|rectangle|ellipse), style:{fillColor,fillOpacity,strokeColor,strokeOpacity,strokeWeight}, path(다각형·선) 또는 center+radius(원) 또는 bounds(사각형·타원), labelPos(선택, 구역 로고를 직접 옮긴 위치) }`. 좌표는 모두 **위도(lat)·경도(lng)**.
- **시설 마커 하나:** `{ id, name, type(시설 유형 id), lat, lng, icon(선택, 이 마커만 다른 아이콘 쓸 때) }`.
- **시설 유형 하나:** `{ id, label, icon:{src,width,height,anchorX,anchorY} }`. `src`는 `public` 폴더 기준 경로(`icons/파일명`), `anchorX·anchorY`는 0~1 기준점(0.5·0.5=정가운데, 0.5·1=아래 가운데).
- 이 파일을 **고치는 방법**은 0-2 "지금 되는 것/앞으로 할 것"에 적힌 대로: 관리자 화면에서 편집 → JSON 내보내기 → `지도 json` 폴더에 **다음 번호로** 저장 → `src/main.js`의 import 경로를 그 번호로 바꿈.

**처음 화면(초기 범위) 설정 — `src/config.js`의 `INITIAL_VIEW`**
- 처음 열었을 때 반드시 보여야 하는 **기준 장소 두 곳**을 주소 또는 위도·경도로 적음(지금: 2.28자유광장, 코오롱야외음악당).
- 지도가 이 장소들이 모두 들어오도록 카카오맵 `LatLngBounds` + `setBounds`로 범위를 자동으로 맞춤. 가장자리 여백(padding)을 둠.
- 화면 너비 **767px**를 기준으로 PC/모바일 설정을 나눠 쓸 수 있음(지금은 둘 다 같은 값).
- 창 크기가 바뀌면(`src/resize.js`) 가운데 좌표는 유지한 채 지도를 다시 맞춤(`relayout`).

**구역·마커를 그리는 법**
- 도형 종류별 좌표 형식과 그리는 법은 2장(코드 번호)·4장(도형·색·라벨)·5장(아이콘)을 따름. 코드상으로는 `src/layers.js`의 `drawZone()`이 `zone.type`에 따라 카카오 Polygon/Polyline/Circle/Rectangle/Ellipse 중 하나를 고름.
- 선(`polyline`·`arrow`)은 가늘어서 누르기 어려우므로, **보이지 않는 굵은 선을 겹쳐서** 클릭 범위를 넓힘(실제 화면엔 안 보임).
- 시설 마커는 `src/markers/markerLayer.js`의 `drawFacilityMarker()`가 `kakao.maps.Marker` + `MarkerImage`로 그림. 아이콘 파일을 못 찾으면 회색 "?" 핀으로 대신 보여 줌(방문객이 깨진 화면을 보지 않게).
- 구역 로고는 4-1-1장 규칙대로 만들고 `config.js`의 `ZONE_LOGOS`에 연결. 자동 배치·드래그 이동은 `src/visitor.js`가 처리.

**만들기 순서 (AI 에이전트가 처음부터 만들 때)**
1. Vite + vanilla JS 프로젝트를 만들고 카카오맵 JavaScript 키를 `.env`에 둠.
2. `index.html`에 지도 담을 영역을 두고, SDK를 `autoload=false`로 불러와 지도를 생성.
3. `INITIAL_VIEW`(이 장)에 따라 처음 화면 범위를 맞춤.
4. 1~9장 규칙(이름·코드·색·도형·아이콘·범례)대로 `지도 json/최종_vN.json` 데이터를 만들고, 그 데이터를 읽어 구역·마커를 그림.
5. 0-2장대로 보기 버튼·스카이뷰·범례를 더함.
6. `npm run build`로 배포용 파일을 만들고, `public/icons`·`public/logos`·데이터 JSON을 함께 옮겨 배포.

- **정의:** 구역 이름 글자를 주인공으로 한 타이틀 로고. 두꺼운 손글씨 레터링 + 두 겹 외곽선(안쪽 흰색·바깥 진한 색) + 아래 입체 그림자. 필요하면 작은 그림(천막·말풍선 등)을 글자에 겹쳐 그림. 배경은 투명.
- **만드는 법**
  1. 이미지 생성 AI(ChatGPT 등)에 "예능 자막 스타일 타이틀 로고"로 요청. 프롬프트에 글자(철자 정확히), 그림 소재, 색, "두 겹 외곽선·입체 그림자·투명 배경"을 적는다.
  2. 완성한 파일을 `festival-map/public/logos` 폴더에 영어 파일명으로 넣는다.
  3. `festival-map/src/config.js`의 `ZONE_LOGOS`에 `구역 이름: { src: '파일경로', width: 가로px }` 한 줄을 추가한다. 세로 길이는 원본 비율대로 자동.
  4. 가로 크기는 **구역마다 다르게** 정한다(지금 68~110px). 고정 크기 규칙은 없고, 다른 로고와 비교해 너무 작거나 크면 width 숫자만 조정한다.
  5. 같은 이름 구역이 여러 곳이면(예: 7구 맛집거리 2곳, 운영부스 3곳) **도형마다 로고를 하나씩** 올린다(0-2 "구역 도형마다 하나씩" 규칙과 동일).
  6. 로고 위치는 구역 안쪽에서 다른 아이콘과 겹치지 않는 자리를 자동으로 찾아 놓인다. 관리자가 방문객 미리보기에서 끌어서 직접 옮기면 그 위치가 저장된다.
  7. **로고 글자에 사투리가 들어가면**, 로고를 만들기 전에 **담당자에게 부제(사투리 뜻)를 로고에 함께 적을지 말지 묻는다.** 에이전트가 마음대로 정하지 않는다. (1-2)

### 6-1. 배치도 범례 (뜻풀이)

> 지도 위에 떠 있는 **플로팅 버튼**(0-2)과는 다른 것. 범례는 누르는 버튼이 아니라 **지도 아래 따로 떨어진 설명 카드**임.

- **뭘 뜻하는지:** 배치도(카카오 지도) 바로 아래에 있는 흰 카드. "이 아이콘이 무슨 시설인지" 아이콘 + 이름으로 한눈에 보여 주는 설명표. 구역 로고는 글자 자체가 이름이라 여기엔 안 넣음(전체지도 범례 쪽에서 구역 이름을 다룸).
- **들어가는 항목:** 지금 지도에 실제로 마커가 있는 시설만. 한 곳도 없는 시설(안내소 등)은 안 보임 — 마커를 새로 놓으면 범례에 자동으로 생김.
- **배치 순서 기준:** 특별한 중요도 순이 아니라, **위쪽 보기 버튼과 똑같은 순서**를 그대로 따름(같은 목록을 코드에서 공유). 화장실 → 더위쉼터 → 의료실 → 소방·응급차 → 수유실 → 축제 출입로 → 무대 → 분실물센터 → **차량 통제**(버튼엔 없지만 범례 맨 끝엔 있음). `[확인]` 지도 담당 (2026-11-25)
