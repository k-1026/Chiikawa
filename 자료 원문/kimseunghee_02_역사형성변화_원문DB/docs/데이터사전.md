## 5. 데이터 사전 요약

- 대상 테이블: CSV 이름 = `kb.<이름>` 표. 적재 순서: source_documents → md_documents → source_sections → knowledge_chunks → chunk_links → md_claims → evidence_links → domain_figures → domain_places → operating_rules → review_issues. `rule_tests.csv`·`search_tests.csv`는 적재하지 않는 테스트 입력.
- 004에서 추가: `knowledge_chunks.region`, `md_claims.stale`, `operating_rules.match_column/match_operator/match_value/warning_text`, 함수 `kb.rule_matches`, 뷰 `kb.v_daesatu_export`.
- 승인 상태: approved = 보관 원문에서 글자 그대로 확인 / reference_only = 기사 스냅숏 대조(미보관) / pending = Aside 보고만·원문 확인 불가 / internal = 원본 MD.
- 값 상태: reported / not_available / unconfirmed / not_applicable / actual_zero. 상한·어림값은 `value_text`만.
- 날짜 칸은 YYYY-MM-DD만(연도만이면 비우고 `published_date_basis`에 기록). 링크 ID는 `CLK-K02-NNNN`.
- 최신성: 생성기가 기준 blob과 현재 main을 비교해 다르면 모든 주장을 `stale=true`로 표시. 검증기는 다른데 표시가 없으면 오류.

## 8. 현재 에이전트 연결 — (나) 선택: kb 유지 + 앱 변경 제안

**확인한 사실**
- 앱(데모 v06)의 지침 검색: `backend/kb_pg_v06.py`가 `knowledge_chunks`(= `daesatu.knowledge_chunks`)를 **임베딩 유사도**(`embedding <=> 질문벡터`)로 조회
- 그 표는 `tools/sync_knowledge_from_repo.py`가 채움. 대상 폴더는 `세부지침안`, `대사투`(.md만). **이 패키지(`자료 원문/`)와 원본 MD(`local 리서치/`)는 대상이 아님**
- `.github/workflows/sync-knowledge.yml`이 main에 `세부지침안/**`·`대사투/**` 변경이 올라올 때마다 동기화하고, **저장소에 없는 조각은 DB에서 지움**

**(가)를 고르지 않은 이유**: `daesatu.knowledge_chunks`에 직접 넣으면 다음 자동 동기화 때 지워집니다(동기화가 저장소 기준으로 지움). 임베딩 컬럼도 NOT NULL이라 이번 규칙(임베딩 호출 금지)으로는 넣을 수 없습니다.

**앱 변경 제안(앱 코드는 고치지 않음)**
1. `kb_pg_v06.py`의 `retrieve`가 `daesatu.knowledge_chunks` 결과와 함께 `kb.search_chunks(question, false, k)`(서비스 역할 또는 authenticated)를 호출해 합치기. 결과의 `warnings`(규칙 경고)를 답변 프롬프트에 함께 넘기기
2. 또는 임베딩으로 통일하려면: `kb.v_daesatu_export`(004, 승인 청크만, 출처 꼬리표 포함, id 접두어 `kb:`)를 읽어 임베딩을 만들고 넣는 별도 단계를 두고, `sync_knowledge_from_repo.py`의 삭제 대상에서 `id like 'kb:%'`를 빼기
3. 어느 쪽이든 `kb.chunk_usability`로 차단·경고 규칙을 답변 전에 확인

임베딩은 만들지 않았고 가짜 벡터도 넣지 않았습니다(적재 후 임베딩 생성 필요).
