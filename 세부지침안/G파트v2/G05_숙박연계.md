# G05 숙박 연계 — 세부 지침

> 구분: 조사 + 연도별 · 기본 지침: v1.1 2장(목표 1순위 1박 체류), 4장, 7장 · 진행: 초안 · 최종 수정: 2026-11-16

## 1. 이 파트의 역할
- 축제 목표 1순위 **"1박 이상 체류"**를 직접 만드는 파트예요 (P0-2).
- 두류공원 주변 숙박 현황과 축제 시기 수요를 조사하고, **숙박 인증 보상**(담당자 결정 2026-11-16 기본 방식)을 설계하고, **1박 체류 비율**을 잴 수 있게 준비해요.
- 읽는 PART: G02(동선 숙박 칸), G03(혜택 지급 창구), G06(숙소 ↔ 축제장 이동), A(타지역 참가자 숙박), I·P0-2(1박 KPI), F(홍보)

## 2. 확정 값

### 2-1. 기본 방식: 숙박 인증 보상

```
사전 신청(웹, K) → 축제 기간 대구 숙소에 1박 → 숙박 인증(영수증·예약 확인) → 보상 수령
```

| 항목 | 기본안 | 근거 |
| --- | --- | --- |
| 대상 | 대구 외 거주자 (주소지 기준), 축제 기간 대구 숙박 | 치맥 '대구 STAY & 골목 PLAY'(언론), 강원 숙박 인증(언론) |
| 인정 숙소 | 대구 소재 숙박업소 전체 (특정 업소 제휴 없이) | 업소 제휴 없이 운영 가능 → 업체 선정 부담 없음 `[해석]` |
| 인증 방법 | 숙박 영수증 또는 예약 확인 화면 + 신분 확인(주소지) | 강원 "6만 원 이상 영수증" 방식 |
| 보상 | 대구로페이 (금액은 2-2 3안) | 치맥 대구로페이 2만 원 |
| 수령처 | 축제장 현장 + 동대구역 관광안내소 | 치맥 동대구역 관광안내소 선례, 민주 04 아이디어 `[가설]` |
| 상한 | 선착순 ○건 (담당자·H 결정) | 치맥 약 5,000명 |

- 비교안: **숙박 플랫폼 할인 쿠폰**(춘천 × 여기어때: 7만 원 미만 2만 원, 이상 3만 원). 플랫폼 협의가 필요해서 기본안이 아니에요. 협의가 되면 G04에서 다시 검토해요.

### 2-2. 보상 금액 3안 `[추정]`

| 최소 | 기본 | 확장 | 근거 |
| --- | --- | --- | --- |
| 10,000원 | 20,000원 | 30,000원 | 치맥 2026 웰컴페이 대구로페이 2만 원(언론), 강원 6만 원 이상 숙박 → 3만 원(언론), 춘천 2~3만 원 쿠폰(언론) |

- 최소 숙박 금액 조건(예: 1박 ○만 원 이상)을 둘지는 담당자가 정해요. 강원은 6만 원 이상이었어요.
- 예산 = 보상 금액 × 상한 건수. 대분류 위치는 P0-6 7장 1번 미확정이에요.

### 2-3. 토론 대회 타지역 참가자 숙박 (A 연계)
- A04는 타지역 참가자에게 숙박을 지원해요 (P0-7). 숙소 확보·비용은 A·H가 정하고, G는 **숙박 밀집 지역과 축제장 이동**(G06) 정보만 넘겨요.

### 2-4. 1박 체류 비율 측정

```
1박 체류 비율 = 숙박 인증 수 ÷ 외지인 방문객 수
```
- 숙박 인증 수: 2-1 인증 집계 (K)
- 외지인 방문객 수: 한국관광 데이터랩(KT 통신 기반)·대구관광 데이터랩으로 교차 확인 (민주 04)
- `[해석]` 숙박 인증은 신청한 사람만 세서 **실제 1박 비율보다 낮게** 나와요. 현장 설문의 "숙박 여부" 문항(I)과 함께 봐요.

## 3. 에이전트 행동 규칙
- 매년 숙박 현황(4장 조사 항목)을 다시 조사해요. 숙박업소 이름은 **"후보"**로만 적고, 제휴·할인을 지어내지 않아요.
- 보상 금액은 3안을 모두 보여 주고 담당자가 골라요. 미확인 비용은 확정값으로 쓰지 않아요.
- 측정 준비(인증 화면, 데이터랩 조회 범위, 설문 문항)는 **D-60 전**에 끝나도록 I·K에 넘겨요 (F07과 같은 기준).
- 8월 말 대구 숙박 수요·가격은 조사한 값만 쓰고 추정하지 않아요. 데이터가 없으면 "확인 안 됨"으로 적어요.
