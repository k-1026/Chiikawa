## 0. 이전 버전과 달라진 점

- **2026-11-20 수정, 검증 결과 반영:** 첫 해 수량 표시를 P0-9 2-1에 맞췄어요. 팀이 정해 준 값은 "팀 입력값(임의 설정)"으로만 적고, 계산한 값만 `[추정]` + 계산식으로 적어요. 값이 없으면 멈춰요 (2-3절). 스탬프 교환용 수량의 원본을 E·M-6에서 H10으로 바꿨어요.
- **2026-11-20 수정, 담당자 답 반영:** "홍보 시작" = **굿즈 사진 첫 공개일 = D-60 (2027-06-21)**으로 정했어요. 입고·검수까지 이날 전에 끝나야 해요 (2-1절, 미확정 1 해결).
- **2026-11-20 수정 추가:** P0-4 V14·H03 2-1이 이미 "홍보 시작 전 입고·검수 완료"인 것을 반영했어요. 2-4·2-5의 단계 번호를 2-2 표에 맞췄어요(⑦ 시작 한계일, ⑤ 생산 파일 점검). 기준 자료 위치 규칙을 3-1에 넣었어요.
- v1: 첫 버전이에요.
- 발주 기준을 2026-11-17 담당자 결정으로 정했어요: **발주 완료는 홍보 시작 전에 끝내고 제작에 들어가야 하고, 입고·검수까지 홍보 시작 전에 끝나야 해요.**
- P0-4 3-1(V14, v12 2026-11-18)과 H03 2-1은 이 결정대로 "홍보 시작 전 굿즈 발주·제작·입고·검수 완료"로 이미 바뀌었어요. 남아 있던 "홍보 시작" 정의(P0-4 7장 11번, H03 7장 1번)는 2026-11-20에 D-60으로 정했어요.
- 발주 **수량** 기준도 정했어요: 첫 해는 팀이 임의로 정하고, 다음 해부터는 판매 KPI를 근거로 예측해요 (2-3절).

## 1. 이 파트의 역할

- 굿즈를 **언제까지 무엇을 끝내야 하는지** 홍보 시작일에서 거꾸로 계산해요: 샘플 → 디자인 확정 → 발주 완료 → 제작 → 입고 → 검수.
- 얼마나 발주할지의 **기준**(첫 해/다음 해)도 정해요. 실제 수량 숫자는 매년 예산·견적·판매 기록을 받아 채워요.
- 디자인 내용은 D03, 예산 입력은 P0-6·H01, 홍보 시작일은 F-5(홍보 캘린더)가 원본이에요. D04는 그 값을 받아서 일정만 계산해요.

## 2. 확정 값

### 2-1. 발주 기준 (2026-11-17 담당자 결정)

- **발주 완료, 제작, 입고, 검수까지 모두 홍보 시작 전에 끝난다.** 전체 판매 물량의 제작·입고·검수가 홍보가 시작되기 전에 완료되어야 한다. (공통 지침서 v01 조건과 같다.)
- 홍보 시작일은 이 파트에서 정하지 않는다. F-5(홍보 캘린더)와 기획자 입력을 받는다. **확정되지 않았으면 임의 날짜를 넣지 않는다.**
- **"홍보 시작" = 굿즈 사진(실물·목업)이 처음 외부에 공개되는 날 = D-60 (담당자 결정 2026-11-20).** F-5의 굿즈 예고 시점(D-60~D-31 "관심" 단계)과 같다. 전체 홍보 시작(D-180)은 기준이 아니다.
- 이유: D-180 기준이면 연도 세부 콘셉트가 나오기 전에 굿즈 디자인을 끝내야 한다.
- 해마다 개최일이 바뀌면 D-60 날짜만 다시 계산한다. 기준(D-60) 자체를 바꾸려면 담당자 결정이 필요하다.

| 해석 | F-5 기준 | 2027 개최일(2027-08-20) 기준 날짜 `[추정]` |
|---|---|---|
| **기준: 굿즈 사진 첫 공개** | D-60~D-31 "관심" 단계의 굿즈 예고 | **D-60 = 2027-06-21** |
| (참고, 기준 아님) 전체 홍보 시작 | D-180 "준비" 단계 시작 (계정 개설·브랜드 키트) | D-180 = 2027-02-21 |

- 계산식: 2027 개최일 2027-08-20 `[확인]` (P0-4 2-1) − 180일 / − 60일. 개최일은 `date`로 계산한 값이다.
- P0-4 3-1(V14)과 H03 2-1은 이미 "홍보 시작 전 발주·제작·입고·검수 완료"다. 입고·검수가 D-60 전에 끝나야 하므로 발주는 D-60보다 훨씬 앞이다. P0-4 7장 11번·H03 7장 1번("홍보 시작" 정의 미정)에는 D-60으로 정해졌다고 알린다.

### 2-2. 일정 계산 (홍보 시작일에서 거꾸로)

아래 단계를 모두 **홍보 시작일에서 거꾸로** 계산한다. 소요 기간은 업체·담당자가 확인한 값만 쓴다. **지어내지 않는다.**

| 순서 | 마감 | 계산 | 필요한 입력 | 상태 |
|---|---|---|---|---|
| ① | 홍보 시작일 = 굿즈 사진 첫 공개일 | D-60 (2027 = 2027-06-21) | 2-1절 담당자 결정 2026-11-20 | 기준 확정 |
| ② | 검수 완료 목표일 | ① − 담당자가 정한 여유 기간 | 여유 기간 | 입력 필요 |
| ③ | 입고 목표일 | ② − (검수·불량 대응 소요) | 담당자 확인 | 입력 필요 |
| ④ | **발주 완료 마감** | ③ − (생산·배송 소요) | 업체 확인 필요 | 입력 필요 |
| ⑤ | 디자인 확정 마감 | ④ − 생산 파일 점검 소요 | 업체 확인 필요 | 입력 필요 |
| ⑥ | 샘플 착수일 | ⑤ − (샘플 제작·배송·검토·수정 소요) | 업체 확인 필요 | 입력 필요 |
| ⑦ | 시작 한계일 | ⑥ − (디자인 개발·가격 조사·업체 견적 소요) | 담당자 확인 | 입력 필요 |

- 발주 완료 마감(④)은 홍보 시작일(①)보다 반드시 앞이어야 한다. 앞서지 않는 일정은 정상 일정으로 제시하지 않는다.
- 모든 기간은 **영업일**인지 **달력일**인지 구분해서 적는다.
- 홍보 시작일, 여유 기간, 업체 소요 기간이 입력되지 않으면 날짜를 계산하지 않고 `입력 필요`로 둔다.

### 2-3. 발주 수량 기준

**첫 해 (과거 판매 자료 없음)**

- **팀이 임의로 정한다** (2026-11-17 담당자 결정). 에이전트는 **팀이 정해 넣어 준 값만 쓴다.** 값이 없으면 `입력 필요`로 두고 8장 미확정 6번으로 보낸 뒤 멈춘다.
- 팀이 넣은 값은 `팀 입력값(임의 설정) — 출처: <파일·날짜>`로 적고 `[추정]`을 붙이지 않는다 (P0-9 2-1: `[추정]`은 계산식이 있는 수치만). 이 값으로 계산한 수량(예: SKU별 배분, 여유율 반영)만 `[추정]` + 계산식으로 적는다.
- 입력받은 예산(P0-6)과 업체 최소 주문 수량 안에서 정한다. 예산을 넘는 수량을 제안하지 않는다.
- 첫 해 자료 없음은 판매 0건이나 낮은 선호가 아니다. 값은 **`미수집`**이다.
- 첫 해에 아래 기록을 반드시 쌓는다 (D05). 다음 해 발주 기준의 근거가 된다.

| 수집 항목 | 기준 (공통 지침서 v01 12절) |
|---|---|
| SKU별 판매 가능 입고 수량 | 불량 제외, 추가 입고는 별도 기록 |
| 순판매 수량·순매출 | 취소·반품 차감, 할인 반영 기준 명시 |
| 판매율 | 순판매 수량 ÷ 판매 가능 누적 입고 수량 × 100. 분모가 0이거나 미수집이면 산출하지 않음 |
| 재고·품절 | 실재고, 불량, 분실, 무상 지급, **품절 시각**을 별도 기록 |
| 방문객 반응 | 문구·캐릭터·상품 선호와 불편 의견. 응답 수·수집 경로 함께 기록 |

**다음 해부터 (판매 KPI 기반 예측)**

- **전년 판매 KPI를 근거로 예측해서 발주 수량 기준을 잡는다.** 예측 방식은 아래 구조를 따른다. (작성자 제안, 팀 검토 전 `[추정]`)

> SKU별 발주 수량 = (전년 순판매 수량 + 품절 보정분) × 규모 보정 × (1 + 여유율)

| 항목 | 규칙 |
|---|---|
| 전년 순판매 수량 | D05 기록. 취소·반품 차감 후 |
| 품절 보정분 | 전년에 **품절된 SKU**는 판매량이 실제 수요보다 낮을 수 있다. 판매량을 상한으로 쓰지 않고, 품절 시각을 보고 상향 여부를 **사람이 판단**한다 |
| 규모 보정 | 전년 대비 방문객·판매 기회 변화. 근거(예상 방문객 등)가 있을 때만 쓰고, 근거가 없으면 1로 둔다 |
| 여유율 | 담당자가 정한다. 이 문서에 숫자를 넣지 않는다 |
| 상·하한 | 예산(P0-6·H01), 업체 최소 주문 수량 |

- 판매율이 높고 품절이 빨랐던 SKU는 늘리고, 재고가 많이 남은 SKU는 줄이는 방향으로 사람이 최종 확인한다. AI는 계산한 값과 근거를 제시하고, **수량은 사람이 확정한다.**
- 전체 방문객 수만으로 굿즈 구매 전환율을 단정하지 않는다. 굿즈 상점 방문 수·구매 건수가 집계됐을 때만 그 정의로 계산한다 (KPI 정의 원본은 I-1).
- 품절 때문에 판매가 멈춘 상품과 선호가 낮은 상품을 구분해서 다음 회차 추천(D02 2-3절)에 반영한다.
- 남은 재고는 판매가 아니라 기부·폐기 기록(D05 2-7절)으로 남기고, 다음 해 수량을 줄이는 근거로 쓴다. 기록용 샘플(수는 D05 2-7 B의 계산식)은 판매 가능 입고 수량에서 미리 뺀다.
- 신규 상품(전년 자료 없음)은 이 식을 쓸 수 없다. 첫 해 기준(임의 설정)을 따르고 `미수집`을 표시한다.
- 스탬프 교환용 굿즈는 판매 수량과 **교환 수량을 따로** 잡는다. 교환용 품목·수량은 H10이 정한 값을 그대로 쓴다 (2027: 손선풍기 150·부채 600, H10 2-5). 다음 해 수량 조정 근거는 H10 기록(날짜별 교환 번호·마감 시각)에서 받는다 (D02 2-4절).

### 2-4. 일정이 안 맞을 때

- 계산 결과 ⑦ 시작 한계일이 이미 지났거나 업체 소요 기간 안에 끝나지 않으면, **수량·옵션·공법 조정안**을 만들어 사람이 선택한다.
  - 예: 옵션(SKU) 수 줄이기, 공법 단순화, 품목 우선순위 조정 (납기 짧은 품목부터).
- **AI가 홍보 시작일이나 검수 단계를 임의로 미루거나 없애지 않는다.**
- 조정안마다 줄어드는 것(옵션·수량·마감 여유)과 늘어나는 위험(불량 대응 시간 부족 등)을 함께 적는다.

### 2-5. 제작 중 검수와 실물 확인

- 실물 샘플 확인 항목은 D03 2-10절을 따른다. 실물 샘플 확인 전에는 양산 승인(D01 2-6절)으로 올리지 않는다.
- **디자인 확정 ≠ 발주 승인.** 디자인 확정 후 생산 파일 점검(⑤ 계산에 들어가는 단계)을 거쳐 발주한다.
- 입고 후 검수에서 불량이 나오면 불량 수량과 원인을 기록하고 판매 가능 입고 수량에서 제외한다 (2-3절 수집 항목).

## 3. 에이전트 행동 규칙

### 3-1. 해야 할 것

- ⚠️ **사람이 해야 하는 일:** 업체·기부처·구청 연락, 발주·기부·폐기 확정, 이미지 생성 도구(ChatGPT 등) 실행. 에이전트는 후보안·확인 항목·작업 카드까지만 만든다 (P0-10 16번). 표의 "D 담당"은 D파트 담당자(사람)다.
- 기준 자료(`Mascot/…`, `Daegu Mascot Lifestyle/…`)는 main `세부지침안/D파트v1/` 아래에 있다 (D00 "기준 자료 위치"). 파일을 읽을 수 없으면 그 작업을 "확인 불가 — 기준 자료 없음"으로 두고 담당자에게 경로를 묻는다. 비슷한 이미지를 찾아 대신 쓰지 않는다.
- 일정을 낼 때 **홍보 시작일 출처**(F-5 또는 기획자 입력)를 적는다. 영업일/달력일을 구분한다.
- 수량은 첫 해인지 다음 해인지를 먼저 밝힌다. 첫 해는 "팀 입력값(임의 설정) — 출처"를 적고(라벨 없음), 계산한 값만 `[추정]` + 계산식으로 적는다. 다음 해는 계산식과 입력 근거를 함께 적는다.
- 홍보 시작일은 굿즈 사진 첫 공개일(D-60) 하나로 계산한다. D-180 기준 일정은 만들지 않는다 (2-1절).
- 품절 SKU는 보정 검토 대상으로 따로 표시한다.

### 3-2. 하면 안 되는 것

- 홍보 시작일, 업체 소요 기간, 여유율, 예산을 임의로 넣기.
- 발주 완료·입고·검수가 홍보 시작 이후로 나오는 일정을 정상 일정으로 제시하기.
- 첫 해 자료 없음을 0건·낮은 선호로 쓰기. 임의 설정 수량을 근거 있는 예측처럼 쓰기.
- 팀이 넣어 주지 않은 첫 해 수량을 만들어 넣거나, 팀 입력값에 `[추정]`을 붙이기.
- 품절된 SKU의 판매량을 그대로 상한으로 쓰기. 전체 방문객 수만으로 구매 전환율 단정하기.
- 사람이 확정하기 전에 발주 수량을 "확정"으로 쓰기.
