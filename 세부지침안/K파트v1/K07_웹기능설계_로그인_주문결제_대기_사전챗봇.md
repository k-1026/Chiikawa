## 2. 지켜야 할 P0 규칙 (기능 설계의 한계선)
0. **웹은 선택이에요. 웹을 쓰지 않아도 축제에 똑같이 참여할 수 있어요.** (2026-11-25 ✅, P0 "편하게 즐긴다")
   - 주문·결제: 현장 결제로 동일하게 가능. 대기번호는 **현장에서 구두로 안내**(✅ 2026-11-25)
   - 현장 안내·지도 인쇄물은 현장에서 제공. 웹에는 스탬프 메뉴·안내·적립·주문 연동을 제공하지 않음
   - 관객 투표만 예외: 웹 로그인 필요(A-3). 휴대폰 없는 관객은 투표 불가, **현장 대체 수단은 두지 않음**(✅ 우선 이대로)
   - **웹 전용 혜택은 없음**(✅): 웹 사용자에게만 가격·메뉴·보상 우대를 주지 않음. 설문 응답 보상도 없음
   - 외국인 등 카카오 계정이 없는 방문객: **온라인 구매·투표를 제외한 모든 것**을 할 수 있어야 함(✅). → **구글 계정 로그인으로 해결**(✅): 투표·열람은 가능, 구매는 현장
1. 사투리 사용은 **선택**. 표준어 주문·참여도 똑같이 가능 (P0-1 2-1, B-7). 사투리 주문 미션은 혜택만 다르게.
2. 모든 부스 메뉴는 **표준어 + 사투리 병기** (예: "부추전(정구지 지지미)").
3. 개인정보 **최소 수집·동의**: 카카오 로그인에서 받는 항목을 필수 최소로(닉네임 등), 온라인 주문자 정보 동의 (D-6, I-3).
4. 10미 메뉴는 7구 존에서 팔지 않음. 업소는 심사 선정 전까지 "후보".
5. 결제 정산은 H-1 소관이고 **웹에서는 정하지 않음**(✅ 2026-11-26).
6. 마스코트는 D-1 검수 (색·설정 변경 금지).
7. 셔틀 문구 넣지 않음, 논제 추천 입력 없음 (K02).

## 2-1. 첫 진입 흐름 (✅ 방향, 세부 🟡)
```
접속 → [카카오 로그인 | 구글 로그인 | 로그인 없이 둘러보기] → 시작 전 1분만요(설문, 건너뛰기 가능) → 홈
주문·투표 시점에 로그인이 필요하면 그때 로그인 화면으로 안내
재방문: 로그인 유지
```
- 설문은 I-4 **사전 설문**과 연결: 사투리 인식 문항은 **사후 설문과 같은 문장**이어야 비교 가능(P0 7번·I-4). 문항 문장은 J·K·I가 정해야 해요(미확정).
- 설문 응답은 카카오 계정 ID와 분리 저장(통계용), 수집 항목·보관기간을 동의 화면에 표시(I-3).
- **사전 설문 문항 (I-4 2-2 필수 8항목, ✅ 2026-11-25)** — 시험판 구현 기준:
  | # | 문항 | 형태 | 비고 |
  |---|---|---|---|
  | 1 | 거주 시·도 | 선택(17개 시·도+해외) | 시·도까지만 |
  | 2 | 연령대 | 단일 선택(10세 단위) | |
  | 3 | 동반 형태(혼자·친구·연인·가족) + 가족이면 자녀 나이대 | 단일 선택 + 조건부 | P0-8 7장 6번 |
  | 4 | 알게 된 경로 | 단일 선택 | **보기는 F-7 채널 목록으로 교체**(임시 보기) |
  | 5 | 방문 예정일(금·토·일) | 복수 선택 | |
  | 6 | 숙박 계획(당일·1박·2박 이상) + 1박 이상이면 숙박 예정 지역(구 단위) | 단일 선택 + 조건부 | |
  | 7 | **사투리 인식 문항** | **5점 척도 동의 문장** | 사후 설문과 **같은 문장**. 임시: "대구 사투리는 친근하게 느껴진다." — J·K와 확정 |
  | 8 | 사후 설문 연락 동의(선택) + 연락 수단 | 단일 선택 | 개인정보 I-3 2-2. 수단 보기: 카카오 알림톡·이메일(임시) |
  - 문항 수 상한 15개(I-4), 현재 8개. 추가 문항은 담당 기획자에게 물어서 넣음.
  - **시점 구분 안 함(✅ 2026-11-25)**: 이 설문은 축제 기간 중 접속한 방문자 정보 수집용이라 I-4의 사전/사후 시점 구분(D-90~D-1 등)은 따지지 않음.
- 사후 설문(M)은 축제 중·후 같은 문항으로 다시 받음.
- 웹을 안 써도 참여 가능하므로(2장 0번) 로그인 선행의 이탈·배제 부담은 줄어요. 그래도 아래 경고는 웹 안에서 유효해요.
- ✅ **로그인 선행 문제는 "둘러보기"로 해결**(2026-11-26). 설문 응답은 기기 단위 익명 토큰으로 저장하고 계정과 연결하지 않으며, 중복 응답은 감수.
- (이전 경고, 참고) ⚠️ 로그인 선행은 P0 "편하게 즐긴다"와 부딪힐 수 있어요: 입구에서 이탈하는 방문객이 생기고 카카오 계정 없는 외국인·고령층은 막혀요. 대안 후보 ❓: ①로그인 선행 유지 ②"로그인 건너뛰고 둘러보기"(주문·투표 때만 로그인).

## 3. 사이트 구조 (K03 개정안 🟡)
하단 탭 5개 + 메뉴(더보기).

| 탭 | 내용 | 로그인 |
|---|---|---|
| ① 홈 | 히어로·핵심 메시지·바로가기·내 대기번호 알림 배너 | 불필요(둘러보기 가능) |
| ② 프로그램·일정 | 행사개요(3대 프로그램+부대) + 시간표(금·토·일) | 불필요 |
| ③ 주문 | 10미·7구 부스 목록 → 메뉴 → 장바구니 → 카카오페이 → 대기번호 | 주문 시 필요 |
| ④ 지도 | 구역·부스 위치, 부스 클릭 시 메뉴·현재 대기 | 불필요 |
| ⑤ 사투리 | 사전·번역기·AI 챗봇 | 불필요 |
| 더보기 | 토론대회(대진표·논제·투표), 숙박 인증, 내 주문·대기, 언어 | 투표·숙박·내 주문은 필요 |

> 토론대회는 하단 탭에서 빼고 **더보기**에 두며, 홈에서 바로가기를 줘요(✅ 2026-11-26).

## 5. 주요 흐름 (🟡 제안)
```
주문:  부스 선택 → 메뉴·수량 → 카카오 로그인 → 카카오페이 → 주문 확정
       → 대기번호 발급(웹) → 조리 중 → 호출(웹 + 알림톡) → 수령
현장:  부스에서 현장 결제 → 부스 화면에서 번호 등록 → 같은 대기 목록에 표시
투표:  토론 페이지 → 카카오 로그인 → 경기 투표(1인 1표) → 득표율
```

## 6. 정한 것과 남은 것 (2026-11-26 확정)
**✅ 확정**
1. **주문 방식**: 웹 주문 → 대기번호 → 부스에서 수령. 현장 구두 주문과 같은 줄에 섭니다.
2. **정산 주체**: **웹에서는 정하지 않아요.** 정산은 H-1 소관이고, 웹 기능·화면에는 반영하지 않습니다.

4. **챗봇**: **행사 정보만** 답해요(일정·위치·주문 방법·사투리 뜻). 주문은 대신 해 주지 않아요. 언어는 한국어·영어. 모를 때: "행사 정보만 답할 수 있어요. 운영·안전 부스에서 안내받을 수 있어요."
5. **하단 탭**: 홈·행사정보·주문·지도·사투리 5개 + 더보기. **토론은 더보기**에 두고 홈에서 바로가기를 줘요.
6. **알림톡은 쓰지 않아요.** 대기 호출은 웹 화면과 팝업으로 알려요.
7. **저장 표**: 지도·시간표는 기존 `웹/supabase` 표를 **읽기만** 하고, 주문·대기·투표·설문은 **새 표**를 만들어요.

## 6-3. POS 연동 방식 (🟡 제안, 공급사 확인 후 확정)
**1단계: 공통 POS 공급사에 확인**
| 확인 항목 | 이유 |
|---|---|
| 외부 주문을 POS로 넣는 API(주문 등록) 제공 여부 | 있으면 웹 주문이 자동으로 POS에 쌓임 |
| 주문 상태 변경 알림(웹훅) 또는 조회 API | 호출·완료를 웹 대기번호에 반영 |
| 오프라인(인터넷 끊김) 모드, 장애 시 복구 방식 | 야외 축제 네트워크 불안 대비 |
| 부스 수만큼 단말·메뉴 등록 지원 | 업소 100여 곳 규모 |

**기본 방식(2026-11-26 ✅): 부스 직원용 관리 화면(수동 입력·접수·완료 처리)**. POS 자동 연동은 아래 결과가 좋을 때의 이후 확장이다. 상세는 [K10](K10_대기번호_코드명세.md).

**2단계: 결과에 따른 분기**
- **API 있음**: 웹 주문 → 자동 POS 접수. 직원 입력 불필요. 대기 순서는 POS 순서 그대로.
- **API 없음(기본 가정)**: 웹 주문이 **부스 태블릿에 알림음과 함께 표시** → 직원이 [접수]를 누르고 POS에 입력 → 같은 주문번호를 POS 영수증에 적음. 이중 입력 부담은 있음(주문 건수 많은 부스는 보조 인력 배치).

**장애 시 대체 절차 (POS 멈춤·인터넷 끊김)**
1. 부스는 **종이 주문표 + 구두 번호**로 전환(오프라인 구두 원칙 그대로).
2. 웹은 해당 부스의 **대기 수·예상 시간을 숨기고** "현장 안내를 따라 주세요"로 표시(잘못된 대기 수 방지). 온라인 주문 접수는 일시 중지 가능.
3. 이미 결제된 카카오페이 주문은 서버에 기록이 남으므로 **주문 목록 인쇄·태블릿 확인**으로 처리.
4. 복구 후 종이 주문을 POS에 일괄 입력, 웹 상태 재개.
5. 부스별 비상 연락처는 **아직 정하지 않음**. 나중에 화면에 문의 번호를 띄움(✅ 2026-11-26).

## 6-5. 전체 에이전트 기획서·결과물에서의 위치 (✅ 방향)
- **웹사이트는 전체 에이전트의 기획서와 결과물에 "선택 사항"으로 들어가요.** 웹을 만들기로 선택한 해에만 포함돼요.
- 선택하면: ① 기획서에 **"웹 발행 전 기획자 확인 항목"**(6-4 표) 섹션이 들어가고, ② 결과물에 웹 데이터 + **발행 전 확인 체크리스트**가 함께 나와요.
- 6-4 항목이 모두 확인·수정되기 전에는 웹을 발행하지 않아요(6-2 검수 단계와 연결). 미확인 칸은 `[기획자 확인 필요]`로 남겨요.
- 웹을 선택하지 않으면 이 항목은 기획서·결과물에 나오지 않아요(웹 없이도 축제 참여 가능 — 2장 0번).
