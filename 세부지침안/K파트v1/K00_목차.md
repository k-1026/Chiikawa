## 5. 에이전트 작업 지시 형식 (웹 제작·연도별 갱신)

전체 순환형 에이전트가 웹사이트를 만들거나 해마다 갱신할 때는 아래 순서와 형식으로 해요. 이유: 필요한 파일만 읽어 토큰을 아끼고, 기능 코드는 건드리지 않기 위해서예요.

**규칙**
1. 먼저 이 K00과 [K07](K07_웹기능설계_로그인_주문결제_대기_사전챗봇.md)의 **6-1 연도별 변경 구조**만 읽는다.
2. 바뀐 파트의 산출물만 읽고, 6-1 매핑표에 있는 **웹 데이터만** 고친다. 기능 코드(로그인·주문·대기·사전·챗봇)는 고치지 않는다.
3. 확정 값과 `[가설]`·미정을 구분해 표시한다(4장 1번).
4. 결과는 파일로 저장하고 이미지는 열어 보지 않는다. 이전 해 데이터 보관은 전체 에이전트가 맡는다.
5. 정해지지 않은 운영 사항(POS 기종·정산·환불·비상 연락처 등)은 **추측하지 말고 마지막에 기획자에게 질문**으로 남긴다([K07](K07_웹기능설계_로그인_주문결제_대기_사전챗봇.md) 6-4).
6. **에이전트는 배포하지 않는다.** 결과물은 K파트 안에 저장하고, 팀이 사람 검수·수정한 뒤 승인해야 배포한다([K07](K07_웹기능설계_로그인_주문결제_대기_사전챗봇.md) 6-2).

**지시 형식**
```
{연도} 버전으로 웹 데이터를 갱신해줘.
기준: {바뀐 파트와 버전, 예: P V15, A파트v7}
바뀐 것: {한 줄씩, 예: 일정 8/19~21, 논제 방식 변경}
K00과 K07 6-1 매핑표에서 해당 항목만 읽고 웹 데이터 파일만 고쳐줘. 기능 코드는 건드리지 마.
```
바뀐 내용을 정리하기 어려우면 "바뀐 것" 대신 새 세부지침안 파일 경로만 준다(이전 버전과 비교해 변경점을 찾는다).
