# 10. 대기번호 — 코드 명세 (K07 4장 "대기번호", 6-3 POS)

> 작성: 2026-11-26 · 설계 허브: [K07](K07_웹기능설계_로그인_주문결제_대기_사전챗봇.md) · 코드: `웹코드/queue/queue.js` · 직원용 관리 화면(예정): `웹코드/queue/staff`

## 1. 규칙: 대기번호는 부스별로 순서대로
- A가 1번 부스에 주문하면 **1번**, 이어서 B가 같은 부스에 주문하면 **2번**이다. 번호는 **부스마다 따로** 센다.
- 번호는 **서버가 붙인다**(두 사람이 동시에 주문해도 겹치지 않도록 DB 순번 사용). 브라우저가 스스로 번호를 정하지 않는다.
- "앞 대기" = 내 번호보다 앞에 있고 아직 호출·완료 안 된 주문 수.
- 상태: `대기(wait)` → `호출(call)` → `수령완료(done)`. 취소는 **부스가 접수하기 전까지만** 사용자가 할 수 있고, 품절·부스 사정 취소는 환불(✅ 2026-11-26).
- **온라인·오프라인 같은 줄**: 현장 구두 주문도 직원이 입력하면 같은 순번에 쌓인다.

> 지금 시험판은 각자 브라우저에만 저장해서 A와 B가 서로를 볼 수 없다. A·B 순번이 맞물리려면 **서버(DB) 공유가 꼭 필요**하다.

## 2. 알림 (2026-11-26 ✅: 웹 화면이 기본, 알림톡은 가능하면 추가)
| 순서 | 방식 | 상태 |
|---|---|---|
| 기본 | 웹 화면의 **실시간 대기번호**(앞 대기 N팀) | 시험판 구현(12초마다 모의 진행) |
| 기본 | 호출 시 **화면 상단 팝업** + (가능하면) 소리·진동. 닫은 경우는 "대기번호는 이 화면에서 확인하세요" 문구 | 시험판은 팝업 모의 |
| 선택 | 브라우저 푸시(허용한 사람만, iOS는 제약) | 후순위 |
| 선택 | 카카오 알림톡 (비즈채널·템플릿 심사·건당 비용) | **MVP 제외, 나중에 추가** |

## 3. 부스 직원용 관리 화면 (기본 방식, ✅ 2026-11-26)
POS 자동 연동이 안 돼도 돌아가도록, 직원이 직접 다루는 웹 화면을 기본으로 둔다.
- 주문 목록(온라인 + 현장 입력), **접수 / 조리중 / 호출 / 완료** 버튼
- **현장 주문 입력**(구두 주문 → 메뉴 선택 → 같은 대기열에 번호 부여)
- 품절 표시, 비밀번호(임시 PIN)로 접근 제한
- POS 자동 연동은 **이후 확장**(공급사·기종 확정 후, K07 6-3)

## 4. 시험판(모의) vs 실제
| | 시험판 | 실제 |
|---|---|---|
| 대기 수 | `base + 내 주문 수` 모의, 12초마다 1칸 | 서버 `queue` 표, 직원 버튼으로 진행 |
| 실시간 갱신 | 12초 타이머 | Supabase Realtime으로 즉시 반영 |
| 직원 화면 | 없음(데모 버튼 "순서 1칸 진행") | `staff` 화면 신설 |

## 5. DB 표 (Supabase, 이름 제안)
**기존 표(읽기 전용, `웹/supabase/schema.sql`의 16개)**: 일정·지도·토론·퀴즈·메뉴 안내 등. 웹은 읽기만 한다.
**새로 만들 표**:

| 표 | 주요 항목 | 권한 |
|---|---|---|
| `booths`, `booth_menus` | 부스(종류 10미/7구, 운영 여부), 메뉴(표준어+사투리, 가격, 품절) | 누구나 읽기 |
| `dictionary_entries` | J-1 사투리 사전 | 누구나 읽기 |
| `orders` | id, booth_id, **queue_no(부스별 순번)**, 항목, 합계, 결제방식(온라인/현장), 상태, 생성시각, 사용자 구분값 |
| `votes` | 경기, 선택, 사용자 구분값(계정당 경기별 1표, 중복 불가) | 로그인 사용자 쓰기 |
| `survey_responses` | 문항별 답(계정과 분리, 익명 토큰) | 누구나 쓰기만, 읽기 불가 |

- 권한은 Supabase의 행 단위 보안(RLS)으로 정한다. 직원 화면의 상태 변경과 정산은 **서버(비밀 키)**만 한다.
- 부스별 대기번호는 DB가 순서대로 붙여 동시에 주문해도 겹치지 않게 한다.
- 실시간 갱신은 표별 Realtime을 켠다.

## 6. 필요한 키
`SUPABASE_URL`·`SUPABASE_ANON_KEY`(공개) / `SUPABASE_SERVICE_ROLE_KEY`(서버) / `STAFF_PIN`(임시) / 알림톡은 선택(`ALIMTALK_API_KEY`)
