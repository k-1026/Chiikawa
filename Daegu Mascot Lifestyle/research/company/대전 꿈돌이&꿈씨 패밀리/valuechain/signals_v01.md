# 병목·비용 신호 체크리스트 — 신호별 확인 위치 (signals_v01)

> 작성 2026-11-08 · 자료에서 마커의 근거를 찾아 쓰는 표예요. 신호마다 어디서 찾는지, 어떤 AI 기회와 짝이 되는지도 함께 적었어요. 근거: [onepager.md](../onepager.md), [analysis_v01.md](analysis_v01.md)(마커 B1·B2·C1·C2·O1~O3), [flows_mermaid_v01.md](flows_mermaid_v01.md), `../sources/`(출처 번호는 `sources/sources.md` 기준, 7은 `local_candidates_v05.md`의 S번호, 8은 팀 문서 `life_메인-v01.md`)
> **규칙(이미지 하단 문구)**: 1장의 예시는 신호의 종류를 보여 주기 위한 **일반 사례**예요. 이 파일의 2장에는 원페이지·리뷰 분석·공시에서 **실제로 확인한 신호만 출처와 함께** 적었고, 확인하지 못한 것은 `[U]`로 비워 뒀어요. 3장 우리 to-be는 확인된 것이 아니라 **가설 `[I]`**이에요.
> 라벨: **[F]** 원문 사실 · **[I]** 해석·가설 · **[U]** 미확인. 이미지의 푸드·물류 체인 예 열은 사용하지 않았어요(콘텐츠 체인만 다룸).

## 1. 신호별 확인 위치 (이미지 형식)

| 신호 | 어디서 찾나 | 콘텐츠 체인 일반 예 | 짝이 되는 AI 기회 |
|---|---|---|---|
| 정보 재입력 | 같은 정보를 단계마다 다시 적는 흔적(상품 정보·출연 정보·주문서) | 콘텐츠 설명·해시태그를 채널마다 수작업 | 문서 → 데이터 추출 자동화 |
| 대기·지연 | 보도자료·리뷰의 "늦게", "품질", "승인 대기" | 캠페인 시안 승인에 여러 단계 | 예측·알림 자동화 |
| 품질 편차 | 리뷰 분석의 불만 키워드, 반품·환불 언급 | 콘텐츠마다 톤이 달라 브랜드 일관성 저하 | 브랜드 스킬 기반 생성·분류 |
| 한 사람 의존 | 인터뷰·보도의 "담당자 한 명", 소규모 생산자 | 기획·촬영·편집을 1인이 | 에이전트 보조·자동 응답 |
| 데이터 단절 | 데이터 흐름 층에서 뒤로 돌아가는 화살표가 없음 | 팬 반응이 다음 콘텐츠 기획에 안 쓰임 | 추천·수요예측 베이스라인 |
| 중간 차감 중첩 | 돈 흐름 층에서 수수료 화살표가 연속 | 플랫폼 + 대행 + 결제 수수료 | D2C·직거래 서비스 시나리오 |

## 2. 대전 꿈돌이(as-is)에서 실제로 확인한 신호

| 정보 재입력 | **부분(약한 단서)** | 홍보관 상품 카탈로그는 "작성일 기준이며 종류·재고·가격은 변경될 수 있음"이라고 적혀 있고, IP 사용 신청은 공익·상업이 서로 다른 경로(온라인 신청 사이트 / 캐릭터 라이센싱 플랫폼)임. **같은 정보를 판매처·경로마다 다시 입력하는지는 확인 못 함** | [출처 1] | [F] 문구 · [U] 재입력 여부 | 마커 없음 · 문서 → 데이터 추출 자동화 |

## 4. 확인하지 못한 신호와 필요한 자료 `[U]`

| 신호 | 못 찾은 것 | 필요한 자료·확인할 곳 |
|---|---|---|
| 대기·지연 · 품질 편차 | 보도자료·리뷰의 "늦게", "품질", "승인 대기" 표현, 리뷰 분석의 불만 키워드, 반품·환불 언급 | 꿈돌이 굿즈·라면 구매 리뷰(채널 미정), 고객 문의 기록 — **리뷰 데이터 소스가 우선 필요** |
| 정보 재입력 | 판매처·신청 경로마다 같은 정보를 다시 입력하는 증거 | 공사 담당 부서 인터뷰, 정보공개 청구 |
| 한 사람 의존 | 담당자 1인·소규모 생산자 여부 | 대전시·공사 협약 보도자료, 인터뷰 |
| 중간 차감 중첩 | 납품 단가·수수료율·꿈씨상회 정산 조건 | 라이센싱 플랫폼 안내, 정보공개 청구 |
| 상업 사용 신청 재개 | 실제 재개 시점 | 공사 사이트 재확인(재개 예정일이 지난 뒤에도 "재개 예정" 문구) |

- [I] 대전에서 근거가 가장 두터운 신호는 **데이터 단절**과 **대기·지연(문구)**이고, 중간 차감은 값이 없어 신호로만 남아요.
