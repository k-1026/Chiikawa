# P세부지침안 동기화 (/p-sync)

인자: `$ARGUMENTS` — `확인만`이면 3단계(영향 찾기)까지만 하고 아무 파일도 고치지 않는다.

## 0. 고정 규칙
- **작업 브랜치는 minju.** 시작할 때 `git branch --show-current`가 minju가 아니면 멈추고 사용자에게 알린다. 다른 브랜치로 직접 옮기지 않는다.
- **minju를 main에 합치지 않는다.** main에는 P 폴더 하나만 교체한다 (6단계).
- 읽는 파일: `P세부지침안/동기화기록.md`, `P세부지침안/파트연결표.md`, 최신 `P세부지침안/P세부지침안VN/`
- 다른 파트 원본 파일은 고치지 않는다. 읽기만 한다.
- P0 작업 규칙은 최신 버전의 `P0-9_공통작업규칙.md`를 따른다 (라벨, 출처, 임의 생성 금지).

## 1. 현재 상태 읽기
1. `git fetch origin`
2. `동기화기록.md`에서 minju 최신 버전 N, main 반영 버전, 최신 버전 상태, 파트별 마지막 반영 커밋을 읽는다.
3. `P세부지침안/` 안의 `P세부지침안V숫자` 폴더 중 가장 큰 숫자가 N과 같은지 확인한다. 다르면 멈추고 알린다.
4. `git status`로 최신 버전 폴더에 커밋 안 된 수정이 있는지 본다. 있으면 "사용자 수정"으로 기록해 둔다 (4단계에서 함께 반영).

## 2. 바뀐 파트 찾기
1. `git ls-tree -d --name-only origin/main 세부지침안/` 로 폴더 목록을 읽는다.
   - 폴더 이름 규칙: `<파트>파트v<숫자>` (예: `B파트v1`, `C파트v2`). P 자신의 폴더(`P파트`)는 제외한다.
   - 한글 경로는 macOS에서 정규화가 달라질 수 있으니 경로는 `git ls-tree -z` 결과를 그대로 쓴다.
2. 파트마다 그 폴더의 최신 커밋을 구한다: `git log -1 --format=%h origin/main -- <폴더>`
3. `동기화기록.md` 2장과 비교해 **새 파트, 버전이 오른 파트, 같은 버전인데 커밋이 바뀐 파트**를 고른다.
4. 바뀐 파트가 없고 1단계의 사용자 수정도 없으면 "업데이트 없음"으로 보고하고 끝낸다. 버전을 올리지 않는다.
5. `파트연결표.md`에 없는 파트가 나오면 표에 줄을 추가할지 사용자에게 묻는다.

## 3. 영향 찾기
바뀐 파트마다:
1. 새 버전 파일을 읽는다 (`git show origin/main:<경로>`). 이전에 반영한 커밋이 있으면 그 커밋의 파일과 비교해 **바뀐 부분만** 본다. 처음 반영하는 파트는 전체를 본다.
2. `파트연결표.md` 1장에서 그 파트가 영향을 주는 P0 파일과 "특히 볼 값"을 찾는다.
3. 바뀐 내용을 아래 셋으로 나눈다.
   - **단순 반영**: 연결표 3장 기준
   - **충돌**: 연결표 2장의 P0 확정값과 다른 값
   - **영향 없음**
4. 결과를 표로 정리한다: `파트 / 파트 문서 위치 / 바뀐 내용 / 영향받는 P0 파일·장 / 분류 / 제안`
5. 인자가 `확인만`이면 이 표를 보여 주고 끝낸다.

## 4. 충돌 묻기
- 충돌이 있으면 AskUserQuestion으로 **한 번에** 묻는다. 항목마다 선택지는 "파트 값으로 바꿈 / P0 값 유지 / 미확정으로 남김".
- "P0 값 유지"를 고르면 P0 파일의 "기본 지침·다른 문서와 다른 점" 표에 차이를 적는다.
- "미확정으로 남김"이면 해당 P0 파일 7장에 `항목 / 이유 / 확인 주체 / 확인 기한`으로 추가한다.

## 5. 새 버전 만들기 (minju)
1. 고칠 폴더 정하기
   - 최신 버전 상태가 **작성 중**이면 `P세부지침안VN/`을 그대로 고친다 (버전 번호 유지).
   - 상태가 **main 반영됨**이어도, 사용자가 "같은 버전으로 다시 올려"라고 하면 번호를 올리지 않고 VN을 고쳐 main의 VN을 덮어쓴다.
   - **main 반영됨**이면 `P세부지침안VN/`을 `P세부지침안V(N+1)/`로 복사하고 그쪽을 고친다. 이전 폴더는 고치지 않는다.
2. 단순 반영 + 충돌 답변 + 사용자 수정을 P0 파일에 반영한다.
   - 고친 파일마다 머리말의 "진행: 확정 vN · 최종 수정: 날짜"를 갱신하고, 맨 아래 변경 이력에 `| 날짜 | vN: <파트>파트v<숫자> 반영 — 바뀐 점 한 줄 |`을 추가한다.
3. 폴더 안 `00_P0_목차.md`의 진행 칸과 머리말 최종 수정일을 갱신한다.
4. 묶음본을 다시 만든다: `P세부지침안VN_묶음본.md` (목차 + P0-1 ~ P0-12 순서 + 예산 입력 양식 부록, 레포 안 상대 링크는 글자만 남김). 머리말에 "이전 버전과 달라진 점"과 "반영한 파트 버전"을 적는다.
5. `동기화기록.md`를 갱신한다: 1장 버전 상태(작성 중), 2장 파트별 마지막 반영 커밋·날짜, 3장 실행 기록 한 줄.
6. minju에 커밋·push한다. `.DS_Store`는 넣지 않는다. 커밋 메시지: `docs: P세부지침안VN — <파트 목록> 반영`

## 6. main에 올리기
1. push 전에 사용자에게 보여 준다: main에 **추가할 폴더**(`세부지침안/P파트/P세부지침안VN/`), **지울 폴더**(main에 있는 이전 `세부지침안/P파트/P세부지침안V*/`), 파일 목록. 확인을 받은 뒤 진행한다.
2. minju 체크아웃은 그대로 두고, 임시 작업 폴더에서 main을 연다.
   ```
   git worktree add --detach <스크래치 경로>/p-sync-main origin/main
   ```
3. 그 작업 폴더에서:
   - 이전 `세부지침안/P파트/P세부지침안V*/` 폴더를 `git rm -r`로 지운다. 단, 같은 번호 VN이 이미 있으면 지우지 않고 그 폴더 파일만 덮어쓴다.
   - minju의 `P세부지침안/P세부지침안VN/`을 `세부지침안/P파트/P세부지침안VN/`으로 복사하고 `git -c core.precomposeunicode=true add`한다. 복사 뒤 `git status`로 새 폴더 파일이 실제로 들어갔는지 확인한다 (한글 경로 누락 방지).
   - 커밋: `세부지침안: P파트 P세부지침안V(N-1)을 P세부지침안VN으로 교체` (같은 버전 갱신이면 `세부지침안: P파트 P세부지침안VN 갱신`)
   - `git push origin HEAD:main`. 거절되면 `git fetch` 후 `git rebase origin/main`으로 다시 올리고, 충돌이 나면 멈추고 알린다. 강제 push는 하지 않는다.
4. 임시 작업 폴더를 정리한다: `git worktree remove <경로>`
5. minju의 `동기화기록.md` 1장을 "main 반영 버전: VN, 상태: main 반영됨"으로 바꾸고, 3장에 main 커밋을 적어 minju에 커밋·push한다.

## 7. 보고
- 반영한 파트와 버전
- P 버전 변화 (예: V2 → V3, 또는 V2 그대로)
- 고친 P0 파일과 바뀐 점 한 줄씩
- 충돌 답변 결과, 새로 생긴 미확정 항목
- minju 커밋, main 커밋
