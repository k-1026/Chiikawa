# 대구 사투리 축제 기획 에이전트 사용법

## 1. 어떤 방식인가
- **Claude Code 레포형 에이전트**예요. 이 깃 레포를 Claude Code로 열면 Claude가 축제 기획 에이전트로 동작해요.
- 에이전트 본체: `지침모음집/대구사투리축제기획에이전트v1/`에 모여 있어요. 본체 문서, 기본 지침, 명령 본문 4개가 들어 있어요.
- 연결 파일: 레포 맨 위 `CLAUDE.md`와 `.claude/skills/`는 Claude Code가 본체를 찾게 하는 얇은 파일이에요. 내용은 본체 폴더에서 고쳐요.
- 근거 자료: `local 리서치/통합_조사결과.md`와 팀원별 원본 폴더예요.

## 2. 처음 한 번 준비

```bash
git clone https://github.com/k-1026/Chiikawa.git
```

```bash
git switch main
git pull
```

그다음 이 폴더를 Claude Code(데스크톱 앱, 터미널 `claude`, VS Code 확장 중 아무거나)로 열어요.

## 3. 매년 쓰는 명령

| 순서 | 명령 | 하는 일 | 만들어지는 파일 |
|---|---|---|---|
| 1 | `/festival-start 2028` | 주최·예산·주제를 묻고 조건과 연간 추진 일정(축제일 역산) 정리 | `local 리서치/2028/00_결정기록.md`, `01_기획조건표.md` |
| 1-1 | `/festival-start 2028 갱신` | 담당자가 정한 것 반영 (주제·날짜·기관 등) | `00_결정기록.md`에 추가, `01` 값 확정 |
| 2 | `/festival-research 2028` | 팀 자료로 근거 정리 + 문제 정의 | `02_조사보고서.md` |
| 3 | `/festival-plan 2028` | 전략·아이디어 평가·프로그램·일정·예산·안전·KPI | `03_기획안.md` |
| 3-1 | `/festival-plan 2028 토론 대회만` | 기획안 중 한 부분만 작성·수정 | `03_기획안.md`의 해당 장 |
| 4 | `/festival-review 2028` | 축제 후 실제 결과 입력 → 성과 분석·내년 과제 | `04_운영결과.md`, `05_차년도과제.md` |

- 명령 대신 "2028 축제 기획 시작해줘"처럼 말로 해도 돼요.
- 새 연도를 시작하면 에이전트가 **전년도 04·05를 먼저 읽어요.** 그래서 4번을 꼭 해 둬야 다음 해 기획이 좋아져요.
- 결정은 사람이 해요. 정한 뒤에는 "2028 주제 A안으로 정했어"처럼 말하면 `00_결정기록.md`에 남고, 다른 단계들이 이 기록을 따라가요.
- 파일 맨 위에 "⚠ … 갱신 필요"가 보이면 결정이 바뀐 거예요. 안내된 명령을 다시 실행해요.
- **KPI 측정은 축제 전에 준비해야 해요.** 03의 "KPI 측정 준비표"대로 숙박 쿠폰, 설문, 데이터 협조를 미리 준비해 두지 않으면, 4번 리뷰를 해도 "측정 안 됨"만 남아요.
- 예산 근거는 `local 리서치/공통/단가표.md`에 쌓여요. 견적서를 받으면 1장에 넣어 두세요. 축제가 끝나면 4번 단계에서 실제 집행액이 자동으로 추가돼요.

## 4. 팀 규칙
- 에이전트가 만든 파일은 **초안**이에요. `[가정]`, `[추정]` 표시는 담당자가 확인해요.
- 조사 자료를 보강하면 `local 리서치/<이름>/` 원본과 `통합_조사결과.md` 요약을 같이 고쳐요.
- 에이전트를 고치는 방법은 `지침모음집/README.md`를 따라요.
- 커밋·push는 에이전트가 알아서 하지 않아요. 확인한 뒤 요청하세요. (커밋 메시지 규칙은 `README.md` 10장)
